## 0. 版本与范围

| 阶段 | 目标 | 包含 |
|---|---|---|
| **M1（本次交付）** | 跑通“账号 → 创作 → 审核 → 阅读/搜索 → 互动/关注/通知 → 治理”闭环 | 登录注册、图文 CRUD、分类树、先审后发、审核、搜索、减少推荐、点赞/收藏、评论/回复、关注/粉丝、站内通知、用户管理、操作日志、浅色主题 |

## 1. 产品定位与价值

### 1.1 一句话定位

一个面向年轻创作者的图文内容社区：创作者低门槛发布，审核者守住内容底线，阅读者能搜索、能互动、能关注作者，并对不感兴趣的内容“减少推荐”。

### 1.2 产品形态

- **前台**：移动优先的图文社区。信息流、分类筛选、搜索、详情阅读、点赞/收藏、评论/回复、关注/粉丝、站内通知。
- **后台**：审核者使用的管理台。内容审核、分类维护、用户增删改查、评论治理、操作日志。
- 前台与后台共用账号体系，但入口、菜单、能力按角色隔离。

### 1.3 目标用户

| 群体 | 典型画像 | 核心诉求 |
|---|---|---|
| 阅读者 | 大学生、职场新人 | 打开就能看、能搜到、能互动、不想看的内容能减少推荐 |
| 创作者 | 普通学生、经验分享者 | 发布简单、审核透明、有人点赞评论、能积累关注 |
| 审核者 | 课程项目中的运营/管理员 | 审核高效、评论可控、分类可管、用户可管、操作可查 |

### 1.4 M1 要解决的问题

1. **内容能发出来**：注册即可创作，发布路径不超过“填标题、正文、分类，提交”。
2. **内容有人守**：文章先审后发；审核者可批量处理；驳回必须给理由。
3. **内容找得到**：按分类浏览，按标题/正文/作者搜索。
4. **内容有人看、有人聊**：点赞、收藏、评论/回复、关注作者；作者能收到站内通知。
5. **用户管得住**：审核者能查、增、改、停用、删除用户，能调整角色，能治理评论。
6. **操作查得清**：登录、审核、用户变更、分类变更、评论治理都有记录。

### 1.5 产品边界

- M1 不做推荐算法；信息流默认按发布时间倒序，另有“关注”流。
- M1 不做深色主题；界面统一浅色，深色/切换 M2。
- M1 不做标签、话题、合集；内容组织只用多级分类。
- M1 不做机器审核、信用分、申诉；文章人工审核，评论敏感词拦截 + 人工治理。
- M1 不做多租户、第三方登录、付费、直播、短视频、私信。

## 2. 用户角色与权限

### 2.1 角色定义

| 角色 | 定义 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 阅读者 | 只浏览和互动的用户 | 浏览、分类、搜索、详情、点赞、收藏、评论、关注、减少推荐、看通知 | 创作、审核、进入后台 |
| 创作者 | 具备发布能力的用户 | 阅读者全部能力 + 新建/编辑/删除自己的内容、提交审核、查看自己的内容状态 | 审核他人内容、管理用户、进入审核后台 |
| 审核者 | 平台运营身份 | 内容审核、批量通过/驳回、下架、分类管理、用户增删改查、评论治理、查看操作日志 | 审核自己创作的内容；删除自己；删除最后一名审核者 |

**注册默认角色**：创作者（含阅读能力）。这样“注册即可创作”，不额外设门槛。
**阅读者角色**：由审核者在用户管理中分配，或用户注册时选择“只看不发布”。
**审核者角色**：只能由现有审核者分配；系统初始化时预置一个审核者账号。

### 2.2 权限矩阵

| 功能 | 阅读者 | 创作者 | 审核者 |
|---|---|---|---|
| 浏览已发布内容 | ✓ | ✓ | ✓ |
| 分类筛选 / 搜索 | ✓ | ✓ | ✓ |
| 点赞 / 收藏 | ✓ | ✓ | ✓ |
| 评论 / 回复 | ✓ | ✓ | ✓ |
| 关注 / 取关 | ✓ | ✓ | ✓ |
| 查看站内通知 | ✓ | ✓ | ✓ |
| 减少推荐 | ✓ | ✓ | ✓ |
| 新建 / 编辑 / 删除自己的内容 | — | ✓ | 建议 — |
| 提交审核 / 撤回 | — | ✓ | — |
| 查看自己的内容状态与理由 | — | ✓ | — |
| 审核 / 批量通过 / 驳回 | — | — | ✓ |
| 下架 / 删除任意内容 | — | — | ✓ |
| 分类新增 / 编辑 / 排序 / 启停 / 删除 | — | — | ✓ |
| 用户查 / 增 / 改 / 停用 / 删除 | — | — | ✓ |
| 调整用户角色 | — | — | ✓ |
| 评论治理（隐藏/删除任意评论） | — | — | ✓ |
| 查看操作日志 | — | — | ✓ |

### 2.3 角色规则

- **审核回避**：审核者不得审核自己创作的内容；若审核者同时创作，自己的内容必须由另一名审核者处理。
- **最后审核者保护**：不能删除、停用或降级最后一名审核者，避免后台无人可用。
- **不能删除自己**：审核者不能删除自己的账号。
- **角色变更留痕**：任何角色调整都写入操作日志。
- **入口隔离**：后台入口只对审核者显示；未授权访问直接拒绝，不暴露后台细节。
- **社交能力不设角色门槛**：只要登录，三种角色都能点赞、收藏、评论、关注；审核者的评论治理是额外能力，不是社交前提。

## 3. 核心业务流程

### 3.1 主流程

```text
注册 / 登录
   ↓
创作者：新建内容 → 保存草稿 → 提交审核
   ↓
审核者：待审列表 → 查看详情 → 通过 / 驳回（理由）
   ↓
通过 → 已发布 → 阅读者：信息流 / 分类 / 搜索 / 详情
   ↓
阅读者：点赞 / 收藏 / 评论 / 关注作者 / 减少推荐
   ↓
作者收到站内通知；关注者的“关注流”出现新内容
```

### 3.2 内容生产（创作者）

- 新建内容：标题、正文、末级分类；封面由系统用“标题 + 纯色背景”自动生成，无需上传。
- 保存草稿：可反复修改；草稿只有作者自己可见。
- 提交审核：状态变为“待审核”，前台不可见。
- 撤回：待审核期间可撤回为草稿。
- 修改：草稿直接改；被驳回后修改再提交；已发布内容修改后重新进入待审核。
- 删除：草稿、已驳回、已下架内容可删除；删除前二次确认。
- 我的内容：按状态筛选，显示驳回/下架理由。

### 3.3 内容审核与运营（审核者）

- 待审列表：按提交时间排序，展示自动封面（标题 + 色块）、标题、作者、分类、提交时间。
- 审核详情：完整预览；通过、驳回、删除。
- 驳回：必须填写理由；作者能看到理由。
- 批量操作：批量通过（即批量发布）、批量驳回、批量下架、批量删除；部分失败要明确提示成功与失败数量。
- 下架：已发布内容可下架，必须填写理由；下架后前台不可见。
- 分类管理：多级分类新增、编辑、排序、启停、删除；有子分类或有内容的分类不能删除。
- 用户管理：查询、新增、编辑、停用、删除、调整角色；停用/删除需理由。
- 评论治理：审核者可隐藏/删除任意评论；处理结果留日志。
- 操作日志：登录、审核、下架、用户变更、分类变更、评论治理均可查。

### 3.4 内容浏览、互动与关注（阅读者 / 创作者）

- **信息流**：只展示已发布内容，按发布时间倒序；卡片含自动封面（标题 + 纯色背景）、作者、分类、点赞数、收藏数、评论数。
- **关注流**：只看已关注作者的已发布内容；未关注任何人时给出引导。
- **分类筛选**：点击任意层级，展示该分类及其子分类下的已发布内容。
- **搜索**：按标题、正文、作者昵称搜索；支持与分类筛选组合；无结果有空态。
- **详情**：自动封面（16:9，标题在封面内）、作者、发布时间、分类、正文；显示点赞/收藏/评论数。
- **点赞 / 收藏**：登录后可操作；重复点击不重复计数；取消后计数回退。
- **评论 / 回复**：一级评论 + 一层回复；评论即时展示，敏感词拦截；作者、文章作者、审核者可删除。
- **关注 / 粉丝**：可关注/取关作者；作者主页显示粉丝数、关注数、已发布内容；不能关注自己。
- **减少推荐**：对某条内容点“减少推荐”，该内容从当前阅读者的信息流中隐藏；不影响其他用户，不删除内容本身。

### 3.5 站内通知

以下事件给相关用户产生站内通知：

| 事件 | 接收者 | 说明 |
|---|---|---|
| 文章审核通过 | 作者 | 含文章标题 |
| 文章被驳回 | 作者 | 含驳回理由 |
| 文章被下架 | 作者 | 含下架理由 |
| 文章被评论 | 文章作者 | 含评论人、评论摘要 |
| 评论被回复 | 被回复人 | 含回复人、回复摘要 |
| 文章被点赞 | 文章作者 | 同一用户重复点赞不重复通知 |
| 文章被收藏 | 文章作者 | 同上 |
| 被关注 | 被关注者 | 含关注人 |

- 通知有未读/已读状态；顶部铃铛显示未读数；支持单条已读、全部已读。
- 不给自己发通知（自己点赞/评论/收藏自己的内容不通知）。
- 通知不改变内容状态，只是提醒。

### 3.6 治理闭环

```text
审核者审核 → 通过 / 驳回 / 下架 → 创作者收到通知
阅读者/创作者互动 → 作者收到通知
审核者治理评论/用户 → 操作日志留痕
```

## 4. 内容状态与生命周期

### 4.1 状态定义

| 状态 | 含义 | 作者可见 | 审核者可见 | 前台公开 |
|---|---|---|---|---|
| 草稿 | 已创建，未提交 | ✓ | — | — |
| 待审核 | 已提交，等待审核 | ✓ | ✓ | — |
| 已发布 | 审核通过 | ✓ | ✓ | ✓ |
| 已驳回 | 审核不通过 | ✓（含理由） | ✓ | — |
| 已下架 | 发布后被撤下 | ✓（含理由） | ✓ | — |
| 已删除 | 作者或审核者删除 | 作者删除后不再显示 | ✓（可追溯） | — |

### 4.2 状态流转

| 当前状态 | 操作 | 操作者 | 结果状态 | 规则 |
|---|---|---|---|---|
| — | 保存草稿 | 创作者 | 草稿 | 可反复保存 |
| 草稿 | 提交审核 | 创作者 | 待审核 | 标题、正文、末级分类齐全 |
| 待审核 | 撤回 | 创作者 | 草稿 | 审核完成前可撤回 |
| 待审核 | 通过 | 审核者 | 已发布 | 记录审核人与时间 |
| 待审核 | 驳回 | 审核者 | 已驳回 | 必须填写理由 |
| 已驳回 | 修改后重新提交 | 创作者 | 待审核 | 展示最新驳回理由 |
| 已发布 | 编辑保存 | 创作者 | 待审核 | 前台立即不可见，重新审核 |
| 已发布 | 下架 | 审核者 | 已下架 | 必须填写理由 |
| 已下架 | 重新上架 | 审核者 | 已发布 | 复核后操作 |
| 草稿 / 已驳回 / 已下架 | 删除 | 创作者 | 已删除 | 二次确认，删除后不再显示 |
| 任意状态 | 删除 | 审核者 | 已删除 | 记录日志，可追溯 |

### 4.3 关键规则

- **BR-01 先审后发**：任何文章未经审核通过，不得出现在信息流、分类、搜索、作者主页、关注流。
- **BR-02 编辑重审**：已发布内容修改后立即从前台撤下，重新进入待审核。
- **BR-03 理由必填**：驳回、下架、停用用户、删除用户都必须填写理由。
- **BR-04 撤回自由**：待审核内容作者可撤回为草稿。
- **BR-05 删除留痕**：删除对前台是消失，对审核者是可追溯；操作日志不可编辑、不可删除。
- **BR-06 下架不等于删除**：下架保留内容，复核后可重新上架；删除是终态。
- **BR-07 状态不可跳跃**：只能按 4.2 流转；非法操作拒绝并提示当前状态。
- **BR-08 审核回避**：不得审核自己创作的内容。
- **BR-09 分类约束**：有子分类或有内容的分类不可删除、不可停用；需先迁移或清空。
- **BR-10 用户保护**：不能删除自己；不能删除、停用或降级最后一名审核者。
- **BR-11 搜索范围**：搜索只返回已发布内容；草稿、待审核、已驳回、已下架不可被搜索到。
- **BR-12 减少推荐**：只影响当前阅读者的信息流，不影响内容状态和其他用户；可在“我的设置”中恢复。
- **BR-13 批量操作**：批量通过/驳回/下架/删除必须给出成功、失败数量；失败项保持原状态。
- **BR-14 密码安全**：密码不得以明文保存，也不得在日志、页面、接口响应中出现。
- **BR-15 权限最小化**：前台不出现后台按钮；后台操作必须再次校验角色与资源归属。
- **BR-16 互动幂等**：重复点赞、收藏、关注不重复计数；取消后计数正确回退。
- **BR-17 评论规则**：评论 1–500 字；一级评论 + 一层回复；即时展示，敏感词拦截；评论作者、文章作者、审核者可删除；删除后计数回退。
- **BR-18 关注规则**：不能关注自己；关注/取关即时生效；关注流只展示已发布内容；取关不删除历史通知。
- **BR-19 通知规则**：只发给相关接收者；不给自己发；未读数准确；单条/全部已读；通知不改变业务状态。
- **BR-20 计数一致**：点赞、收藏、评论、粉丝、关注数必须与实际记录一致；取消/删除后立即回退。
- **BR-21 文章与评论审核差异**：文章“先审后发”；评论“即时展示 + 敏感词拦截 + 事后治理”。评论被删除后不再展示，但操作留日志。
- **BR-22 个人主页**：公开展示昵称、头像、简介、粉丝/关注数、已发布内容；不展示草稿、待审、驳回、下架内容。

## 5. 功能需求

### 5.1 总览

| 编号 | 模块 | 优先级 | 说明 |
|---|---|---|---|
| FR-AUTH | 注册 / 登录 / 退出 | P0 | 账号、密码、角色入口 |
| FR-USER | 用户管理 | P0 | 审核者对用户增删改查、角色分配 |
| FR-CAT | 分类管理 | P0 | 多级分类树、排序、启停、删除约束 |
| FR-ART | 内容创作 | P0 | 图文增删改查、草稿、提交、撤回 |
| FR-REV | 内容审核 | P0 | 待审、通过、驳回、批量、下架 |
| FR-READ | 浏览与搜索 | P0 | 信息流、关注流、分类筛选、搜索、详情 |
| FR-INT | 点赞 / 收藏 | P0 | 幂等、计数、我的收藏 |
| FR-COM | 评论 / 回复 | P0 | 一级评论 + 一层回复、治理 |
| FR-FOL | 关注 / 粉丝 | P0 | 关注/取关、关注流、主页 |
| FR-NOT | 站内通知 | P0 | 审核结果、评论、点赞、收藏、关注 |
| FR-LOG | 操作日志 | P0 | 登录、审核、用户、分类、评论治理 |
| FR-ME | 个人中心 | P0 | 我的内容、收藏、关注、资料 |

### 5.2 FR-AUTH 注册 / 登录 / 退出

- 注册：用户名、密码、昵称；用户名唯一；密码有强度提示。
- 登录：用户名 + 密码；失败提示不泄露“账号是否存在”。
- 退出：清除登录状态，回到首页。
- 角色入口：登录后按角色展示菜单；阅读者/创作者看不到后台入口。
- 停用账号：登录时提示“账号已停用”及原因。
- 验收：注册后可登录；错误密码被拒绝；停用账号不能登录；退出后受保护页面不可访问。

### 5.3 FR-USER 用户管理（审核者）

- 列表：按用户名/昵称搜索，展示角色、状态、注册时间。
- 新增：审核者可直接创建用户，指定用户名、昵称、初始密码、角色。
- 编辑：修改昵称、角色、状态；用户名不可改。
- 停用 / 启用：停用需理由；停用后该用户不能登录。
- 删除：逻辑删除；需理由；不能删除自己；不能删除最后一名审核者。
- 角色分配：阅读者 / 创作者 / 审核者；调整后立即生效。
- 验收：新增用户能登录；停用后不能登录；角色调整后菜单变化；最后一名审核者无法被删除/降级。

### 5.4 FR-CAT 分类管理

- 多级分类树：新增子分类、编辑名称、调整排序、启用/停用、删除。
- 分类与内容绑定：创作者提交时必须选择末级分类。
- 前台：只展示启用分类；父分类筛选包含全部子分类内容。
- 删除约束：有子分类或有内容的分类不可删除；停用同样受限。
- 验收：新增分类后创作页可选；父分类能筛出子分类内容；违规删除被拒绝并提示原因。

### 5.5 FR-ART 内容创作

- 新建：标题（必填）、正文（必填）、末级分类（必选）。
- 封面：系统自动生成“标题 + 纯色背景”的 3:4 封面，无需上传；标题过长时最多展示 3 行并省略。
- 草稿：可反复保存；离开前提示未保存。
- 提交：校验必填；提交后状态为待审核，前台不可见。
- 撤回：待审核可撤回为草稿。
- 编辑：草稿直接改；已驳回修改后重提；已发布修改后重新审核。
- 删除：二次确认；删除后从“我的内容”移除。
- 我的内容：按状态筛选，显示驳回/下架理由。
- 验收：缺标题/分类不能提交；提交后前台不可见；已发布编辑后前台立即消失；无需上传封面也能看到自动封面。

### 5.6 FR-REV 内容审核

- 待审列表：自动封面、标题、作者、分类、提交时间；默认先提交先审。
- 筛选：按分类、标题/作者关键词筛选。
- 详情：完整预览；展示作者、分类、历史审核记录。
- 通过：变为已发布，记录审核人与时间；给作者发通知。
- 驳回：必须填写理由；可选常用理由（含广告、分类错误、内容不完整）；给作者发通知。
- 批量：批量通过（即批量发布）、批量驳回、批量下架、批量删除；给出成功/失败数量。
- 下架：已发布内容可下架，必须填写理由；给作者发通知。
- 删除：严重违规可直接删除，记录日志。
- 并发：两人同时处理同一条，只有一人成功，另一人提示“已被处理”。
- 验收：通过后前台可见；驳回理由作者可见；批量操作失败项状态不变。

### 5.7 FR-READ 浏览与搜索

- 信息流：只展示已发布内容；按发布时间倒序；卡片含自动封面（标题 + 纯色背景）、作者、分类、点赞/收藏/评论数。
- 关注流：只展示已关注作者的已发布内容；按发布时间倒序；空关注时引导去发现。
- 分类筛选：任意层级；父分类包含子分类。
- 搜索：标题、正文、作者昵称；可与分类组合；无结果有空态。
- 详情：自动封面（16:9，标题在封面内）、作者、发布时间、分类、正文、点赞/收藏/评论数；返回列表保留位置。
- 减少推荐：对内容点“减少推荐”，当前阅读者的信息流不再展示；可在设置中恢复。
- 自动封面：标题最多 3 行，超出省略；纯色背景从预设色板中选；信息流 3:4、详情 16:9；无需上传图片。
- 验收：非公开内容不出现在任何列表/搜索/关注流；搜索无结果有空态；减少推荐只影响当前账号；无上传封面也能看到自动封面。

### 5.8 FR-INT 点赞 / 收藏

- 点赞 / 取消点赞：登录后可用；按钮表现为二态开关（亮/灭），重复点击或网络重试不重复计数；刷新后状态保持。
- 收藏 / 取消收藏：同上；“我的收藏”可查看并取消。
- 计数：卡片、详情、个人主页展示的计数与实际一致。
- 通知：别人点赞/收藏我的文章时，给我发通知；自己操作自己的文章不发。
- 验收：未登录点击引导登录；重复点赞计数不变；取消后回退；我的收藏可取消。

### 5.9 FR-COM 评论 / 回复

- 评论：登录后在已发布文章下发表 1–500 字评论；即时展示。
- 回复：对一级评论回复，最多一层；回复展示在父评论下。
- 删除：评论作者可删自己的；文章作者可删自己文章下的评论；审核者可删任意评论。
- 敏感词：命中敏感词的评论不展示，提示“内容包含敏感词”。
- 计数：文章评论数只统计可见评论；删除后回退。
- 通知：评论文章 → 通知文章作者；回复评论 → 通知被回复人；自己操作自己不发。
- 验收：未登录不能评论；空评论/超长被拒绝；回复层级正确；删除权限正确；计数正确。

### 5.10 FR-FOL 关注 / 粉丝

- 关注 / 取关：登录后可用；不能关注自己；重复关注不重复计数。
- 粉丝 / 关注列表：作者主页展示粉丝数、关注数；可查看列表（分页）。
- 关注流：只展示已关注作者的已发布内容；取关后不再出现新内容。
- 通知：被关注时给被关注者发通知。
- 验收：不能关注自己；重复关注计数不变；关注流只出已关注作者；取关后关注流更新。

### 5.11 FR-NOT 站内通知

- 通知类型：审核通过、驳回、下架、评论、回复、点赞、收藏、关注。
- 列表：按时间倒序；显示类型、来源用户、目标内容摘要、时间、已读状态。
- 未读数：顶部铃铛显示未读数；进入列表后可单条已读/全部已读。
- 跳转：点击通知进入对应文章/评论/用户主页；目标已删除时给出提示。
- 验收：审核后作者收到通知；评论后文章作者收到；点赞/收藏/关注各收到一次；未读数准确；已读后减少。

### 5.12 FR-LOG 操作日志

- 记录范围：登录、退出、文章审核（通过/驳回/下架/删除）、用户新增/编辑/停用/删除/角色调整、分类新增/编辑/排序/启停/删除、评论治理。
- 字段：时间、操作人、动作、对象类型、对象标识、结果、理由。
- 查询：按时间范围、操作人、动作、对象类型筛选；按时间倒序。
- 不可编辑、不可删除；审核者只能查看。
- 验收：完成一次审核/治理后能查到记录；普通用户看不到日志入口。

### 5.13 FR-ME 个人中心

- 我的内容：按状态筛选，显示状态与理由；提供编辑、撤回、删除入口。
- 我的收藏：列表 + 取消收藏。
- 我的关注 / 粉丝：列表 + 取关。
- 我的通知：入口与未读数。
- 基本资料：昵称、头像、简介（可选）。
- 我的设置：恢复被“减少推荐”的内容。
- 验收：作者只能看到自己的非公开内容；不能通过改地址查看他人草稿；收藏/关注列表正确。

## 9. 非功能性业务要求

### 9.1 视觉与体验基调

- **风格**：M1 统一浅色；纯白画布、`#333` 文字、`#FF2442` 品牌红点睛；卡片无边框、无阴影；参考 `docs/UIUX-小红书.md`。深色/切换 M2。
- **信息流**：自动封面 3:4 卡片；桌面 5 列、平板 3 列、手机 2 列；顶栏 72 + 左栏 219；移动端底部导航；状态用颜色 chip 区分（草稿灰、待审琥珀、已发布绿、驳回红、下架紫）。
- **自动封面**：纯色背景 + 标题，最多 3 行；颜色从预设色板中选，同一文章保持稳定；不依赖图片上传。
- **详情**：桌面 1066×836 双栏弹层（左 3:4 封面、右内容/评论/操作栏）；移动端全屏；标题只出现一次。
- **互动**：点赞/收藏按钮即时反馈；评论输入框固定在评论区顶部；关注按钮状态明确；通知铃铛显示未读数。
- **操作**：搜索输入即筛选；列表局部刷新不丢滚动位置；危险操作二次确认；失败保留用户输入。
- **空态 / 错误态**：说明“为什么空、下一步做什么”，不写技术术语；关注流为空时引导去发现。
- **适配**：移动端可浏览；后台表格在窄屏横向滚动，不挤压列。
- **动效**：卡片不抬升、不缩放；只做 0.15–0.2s 颜色/背景过渡；尊重系统“减少动态效果”设置。

### 9.2 质量要求

- **可启动**：按交付说明启动后，登录、发布、审核、搜索、互动主链路可用。
- **可演示**：准备一组种子数据（用户、分类、已发布内容、评论、关注、通知），答辩时不依赖现场造数。
- **安全**：密码加密保存；未登录不能操作；越权访问被拒绝；输入有校验；错误提示不泄露内部细节。
- **可追溯**：审核、用户、分类、评论治理都有日志；日志不可删改。
- **体验**：移动端可浏览；列表分页/加载有反馈；空态、错误态明确；高危操作二次确认。
- **性能**：列表分页，不一次性加载全表；搜索与筛选在可接受时间内返回。
- **兼容**：Chrome / Edge 最新版可正常使用。

## 11. M1 默认约定

以下为当前建议，评审时可改：

1. **注册默认角色为创作者**（含阅读能力）；阅读者角色由审核者分配或注册时选择。
2. **审核者不参与创作**；若后续允许，必须遵守审核回避。
3. **封面自动生成（标题 + 纯色背景），正文至少 1 个字**；标题、正文字数上限在开发前定稿。
4. **“减少推荐”仅隐藏当前账号的信息流**，可在设置中恢复；不删除内容。
5. **删除均为“前台消失、后台可追溯”**；不提供作者恢复入口。
6. **M1 信息流按发布时间倒序**；关注流同样按时间倒序；不做推荐排序。
7. **M1 评论即时展示**，敏感词拦截 + 事后治理；文章仍然先审后发。
8. **M1 只做浅色主题**；深色/切换 M2。
9. **M1 通知只做站内**，不做邮件/短信/推送；点赞/收藏/关注每事件一条，不做聚合。

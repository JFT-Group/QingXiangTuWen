# 轻享图文 · 接口文档（M1）

> 项目名暂定「轻享图文」，后续可能改名；接口路径中的 `qingxiang` 只是当前代号。
>
> 适用版本：M1（核心 CMS + 社交闭环）。配套《产品需求与业务说明书》《开发规范》《模块划分与分工》。
>
> 配套交付物：本文档是接口单一来源；ApiFox 集合按本文档生成，路径 `docs/apifox/qingxiang-api.postman_collection.json`（Postman v2.1，ApiFox 可导入），由模块 A 维护模板、各模块补自己的请求。

## 1. 通用约定

### 1.1 Base URL

```text
http://127.0.0.1:18080/qingxiang/api/v1
```

- 页面路由（JSP）不在本文档范围；本文档只写 JSON API。
- 所有接口返回 `application/json; charset=UTF-8`；上传接口用 `multipart/form-data`。

### 1.2 登录态

- 登录使用 **Session**：登录成功后服务端返回 `Set-Cookie: JSESSIONID=...`，后续请求带 Cookie。
- 登录响应同时返回 `csrfToken`；非 `GET` 请求必须带 `X-CSRF-Token` 头（或表单 `_csrf`）。
- 未登录访问页面 → 302 `/login`；未登录访问 `/api/**` → HTTP 401 + JSON。
- 退出登录后旧 Cookie 失效。

### 1.3 统一响应

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

- `code` 与 HTTP 状态码一致：200 / 400 / 401 / 403 / 404 / 409 / 413 / 500。
- 成功无数据时 `data` 为 `null`。
- 错误 `message` 是给用户看的中文，不包含堆栈、SQL、类名。
- 所有时间使用 ISO-8601：`2026-11-18T10:00:00+08:00`。

### 1.4 分页

请求：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `page` | int | 1 | 从 1 开始 |
| `size` | int | 10 | 最大 50，超过按 50 |

响应：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [],
    "total": 128,
    "page": 1,
    "size": 10
  }
}
```

### 1.5 枚举

| 枚举 | 取值 |
|---|---|
| 角色 `roleCode` | `READER` / `CREATOR` / `REVIEWER` |
| 用户状态 `status` | `ACTIVE` / `DISABLED` |
| 文章状态 `status` | `DRAFT` / `PENDING` / `PUBLISHED` / `REJECTED` / `UNPUBLISHED` |
| 审核动作 `action` | `APPROVE` / `REJECT` / `UNPUBLISH` / `DELETE` |
| 评论状态 `status` | `VISIBLE` / `HIDDEN` |
| 通知类型 `type` | `ARTICLE_APPROVED` / `ARTICLE_REJECTED` / `ARTICLE_UNPUBLISHED` / `COMMENT` / `REPLY` / `LIKE` / `FAVORITE` / `FOLLOW` |
| 通知目标 `targetType` | `ARTICLE` / `COMMENT` / `USER` |

> API 用字符串枚举；数据库存 `TINYINT`，由后端枚举转换，前端不要依赖数字。

### 1.6 错误码

| HTTP / code | 含义 | 典型场景 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 参数或业务校验失败 | 缺字段、标题超长、评论含敏感词、理由为空 |
| 401 | 未登录 / 会话失效 | 未登录访问受保护接口 |
| 403 | 无权限 | 阅读者发文章、创作者审核、越权删他人内容 |
| 404 | 不存在 | 文章/评论/用户不存在或已删除 |
| 409 | 状态冲突 / 重复 | 审核已被处理、重复用户名、状态不允许 |
| 413 | 文件过大 | 头像/图片上传超过限制 |
| 500 | 系统错误 | 未预期异常 |

### 1.7 权限码

| 权限码 | 说明 | 角色 |
|---|---|---|
| `article:create` | 新建文章 | CREATOR |
| `article:update` | 编辑自己的文章 | CREATOR |
| `article:delete` | 删除自己的文章 | CREATOR |
| `article:submit` | 提交/撤回 | CREATOR |
| `article:review` | 通过/驳回 | REVIEWER |
| `article:unpublish` | 下架/重新上架 | REVIEWER |
| `article:batch` | 批量审核 | REVIEWER |
| `comment:manage` | 评论治理 | REVIEWER |
| `category:manage` | 分类管理 | REVIEWER |
| `user:manage` | 用户管理 | REVIEWER |
| `log:view` | 查看日志 | REVIEWER |

> 登录用户都可点赞、收藏、评论、关注、看通知、减少推荐；这些不需要额外权限码。

## 2. 认证与账号（模块 A）

### 2.1 注册

`POST /auth/register` · 公开

请求：

```json
{
  "username": "creator01",
  "password": "123456",
  "nickname": "小创"
}
```

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `username` | string | 是 | 4–50，唯一，字母/数字/下划线 |
| `password` | string | 是 | 6–72 |
| `nickname` | string | 是 | 1–50 |

响应 `data`：

```json
{
  "id": 3,
  "username": "creator01",
  "nickname": "小创",
  "roleCode": "CREATOR"
}
```

错误：400（参数/用户名重复）、500。

### 2.2 登录

`POST /auth/login` · 公开

请求：

```json
{ "username": "creator01", "password": "123456" }
```

响应 `data`：

```json
{
  "user": {
    "id": 3,
    "username": "creator01",
    "nickname": "小创",
    "avatarUrl": null,
    "bio": null,
    "roleCode": "CREATOR",
    "roleName": "创作者",
    "status": "ACTIVE",
    "followerCount": 0,
    "followingCount": 0
  },
  "permissions": ["article:create", "article:update", "article:delete", "article:submit"],
  "csrfToken": "a1b2c3...",
  "unreadCount": 0
}
```

错误：400（参数）、401（用户名或密码错误）、403（账号停用，message 含原因）。

### 2.3 退出

`POST /auth/logout` · 登录 · 需 CSRF

响应：`data: null`。错误：401。

### 2.4 当前用户

`GET /auth/me` · 登录

响应 `data` 同登录的 `user + permissions + unreadCount`。

### 2.5 刷新 CSRF

`GET /auth/csrf` · 登录

响应：

```json
{ "csrfToken": "a1b2c3..." }
```

## 3. 用户管理（模块 A，审核者）

### 3.1 用户列表

`GET /admin/users` · `user:manage`

Query：

| 参数 | 类型 | 说明 |
|---|---|---|
| `keyword` | string | 用户名/昵称模糊 |
| `roleCode` | string | 角色筛选 |
| `status` | string | ACTIVE / DISABLED |
| `page` / `size` | int | 分页 |

响应 `data.list[]`：

```json
{
  "id": 3,
  "username": "creator01",
  "nickname": "小创",
  "avatarUrl": null,
  "roleCode": "CREATOR",
  "roleName": "创作者",
  "status": "ACTIVE",
  "createTime": "2026-11-18T10:00:00+08:00"
}
```

### 3.2 新增用户

`POST /admin/users` · `user:manage` · 需 CSRF

```json
{
  "username": "reader01",
  "password": "123456",
  "nickname": "读者一",
  "roleCode": "READER"
}
```

响应：新建用户 VO。错误：400（用户名重复/参数）、403。

### 3.3 用户详情

`GET /admin/users/{id}` · `user:manage`

响应：用户 VO + `followerCount` / `followingCount` / `articleCount`。

### 3.4 编辑用户

`PUT /admin/users/{id}` · `user:manage` · 需 CSRF

```json
{
  "nickname": "新昵称",
  "avatarUrl": "/api/v1/files/2026/11/xxx.webp",
  "bio": "简介",
  "roleCode": "CREATOR"
}
```

- 用户名不可改。
- 修改角色受“最后审核者保护”约束。
- 响应：更新后的用户 VO。

### 3.5 调整角色

`PUT /admin/users/{id}/role` · `user:manage` · 需 CSRF

```json
{ "roleCode": "REVIEWER" }
```

错误：400（降级最后一名审核者）、403、404。
成功后目标用户 `session_version + 1`，现有会话失效，需重新登录后按新权限生效。

### 3.6 停用 / 启用

`PUT /admin/users/{id}/status` · `user:manage` · 需 CSRF

```json
{ "status": "DISABLED", "reason": "多次违规" }
```

- `DISABLED` 必须带 `reason`。
- 不能停用自己；不能停用最后一名审核者。
- 停用后目标用户 `session_version + 1`，现有会话失效，不能继续操作。
- 响应：`{ "id": 3, "status": "DISABLED" }`。

### 3.7 删除用户

`DELETE /admin/users/{id}?reason=...` · `user:manage` · 需 CSRF

- 逻辑删除；需理由；不能删自己；不能删最后一名审核者。
- 响应：`data: null`。错误：400/403/404。

## 6. 文章（模块 B）

### 6.1 信息流 / 搜索

`GET /articles` · 公开

Query：

| 参数 | 类型 | 说明 |
|---|---|---|
| `keyword` | string | 标题/正文/作者昵称模糊 |
| `categoryId` | long | 分类（包含子分类） |
| `authorId` | long | 作者筛选 |
| `sort` | string | `latest`（默认）/ `oldest` |
| `page` / `size` | int | 分页 |

- 只返回 `status=PUBLISHED` 且 `deleted=0`。
- 响应 `data.list[]`：文章列表 VO，含 `coverColor`、`likeCount/favoriteCount/commentCount`。
- `coverColor` 是自动封面的纯色背景（`#RRGGBB`）；前端用 3:4 色块 + 标题渲染，不请求图片。

### 6.2 关注流

`GET /articles/following` · 登录

Query：`page`、`size`、`sort`（默认 latest）。

- 只返回当前用户关注作者的已发布文章。
- 没有关注时返回空列表 + `data.emptyHint`（可选）。

### 6.3 文章详情

`GET /articles/{id}` · 公开（非公开仅作者/审核者）

响应 `data`：

```json
{
  "id": 10,
  "title": "周末探店",
  "coverColor": "#15803d",
  "content": "<p>...</p>",
  "status": "PUBLISHED",
  "authorId": 3,
  "authorName": "小创",
  "authorAvatar": null,
  "categoryId": 5,
  "categoryName": "美食 / 探店",
  "likeCount": 12,
  "favoriteCount": 3,
  "commentCount": 4,
  "liked": true,
  "favorited": false,
  "followedAuthor": false,
  "rejectReason": null,
  "publishTime": "2026-11-18T10:00:00+08:00",
  "createTime": "2026-11-17T09:00:00+08:00"
}
```

- 非公开文章：作者/审核者可看，其他人 404（不泄露存在性）。
- `liked/favorited/followedAuthor` 未登录为 `false`。
- `coverColor` 为自动封面背景色；前端用固定 3:4 色块 + 标题渲染，不请求图片。

### 6.4 新建草稿

`POST /articles` · `article:create` · 需 CSRF

```json
{
  "title": "周末探店",
  "content": "<p>正文</p>",
  "categoryId": 5
}
```

- 标题 1–120；正文必填；分类必须是启用的末级分类。
- 不接收封面上传：服务端按标题哈希从预设色板选 `coverColor`，随文章返回；标题过长由前端 3 行省略。
- 新建后 `status=DRAFT`。
- 响应：文章详情 VO（`status=DRAFT`）。

### 6.5 编辑文章

`PUT /articles/{id}` · `article:update` · 需 CSRF

请求同新建。

- 只能编辑自己的文章；草稿/驳回/下架可直接改；已发布保存后 `status=PENDING`，前台立即不可见。
- 响应：更新后的文章 VO。

### 6.6 删除文章

`DELETE /articles/{id}` · `article:delete` · 需 CSRF

- 逻辑删除；只能删自己的；二次确认在前端。
- 响应：`data: null`。

### 6.7 提交审核

`POST /articles/{id}/submit` · `article:submit` · 需 CSRF

- 草稿/已驳回 → 待审核；校验标题、正文、末级分类。
- 响应：`{ "id": 10, "status": "PENDING" }`。
- 错误：400（缺项）、409（状态不允许）。

### 6.8 撤回

`POST /articles/{id}/withdraw` · `article:submit` · 需 CSRF

- 待审核 → 草稿。
- 响应：`{ "id": 10, "status": "DRAFT" }`。

## 8. 审核（模块 B）

### 8.1 待审列表

`GET /reviews` · `article:review`

Query：`keyword`、`categoryId`、`page`、`size`。

响应：文章列表 VO 分页（`status=PENDING`），含作者、分类、提交时间。

### 8.2 审核详情

`GET /reviews/{id}` · `article:review`

响应：文章详情 VO + `reviewLogs[]`（历史审核记录：动作、审核人、理由、时间）。

### 8.3 通过

`POST /reviews/{id}/approve` · `article:review` · 需 CSRF

- 仅 PENDING；条件更新；成功写 `review_time/reviewer_id`、发作者通知。
- 响应：`{ "id": 10, "status": "PUBLISHED" }`。
- 错误：409（已被处理）。

### 8.4 驳回

`POST /reviews/{id}/reject` · `article:review` · 需 CSRF

```json
{ "reason": "含广告" }
```

- 理由 1–500，必填；发作者通知。
- 响应：`{ "id": 10, "status": "REJECTED" }`。

### 8.5 批量审核

`POST /reviews/batch` · `article:batch` · 需 CSRF

```json
{
  "ids": [10, 11, 12],
  "action": "APPROVE",
  "reason": ""
}
```

- `action`：APPROVE / REJECT / UNPUBLISH / DELETE；REJECT/UNPUBLISH 必须带 reason。
- 逐条事务，部分成功。

响应：

```json
{
  "successCount": 2,
  "failCount": 1,
  "failures": [
    { "id": 12, "message": "该内容已被处理" }
  ]
}
```

### 8.6 下架

`POST /admin/articles/{id}/unpublish` · `article:unpublish` · 需 CSRF

```json
{ "reason": "内容不实" }
```

- 仅 PUBLISHED；理由必填；发作者通知。
- 响应：`{ "id": 10, "status": "UNPUBLISHED" }`。

### 8.7 重新上架

`POST /admin/articles/{id}/republish` · `article:unpublish` · 需 CSRF

- 仅 UNPUBLISHED；复核后操作；响应 `{ "id": 10, "status": "PUBLISHED" }`。

## 9. 文件上传（模块 B）

### 9.1 封面（自动生成，无上传接口）

- 文章创建/编辑**不接收封面文件**；封面 = 标题 + 纯色背景。
- 服务端按标题哈希从 6 色预设中选 `coverColor`，随列表/详情返回；编辑标题不改色。
- 前端渲染 3:4 色块 + 标题（最多 3 行）+ 分类小字；不请求图片。
- M2 若加自定义封面，再增加 `coverUrl` 可选字段；M1 不做。

### 9.2 头像上传

`POST /files/avatar` · 登录 · 需 CSRF · `multipart/form-data`

- jpg/png/webp，≤2MB；响应为 `{url,width,height,size}`（建议 1:1）。

### 9.3 访问文件

`GET /files/{yyyy}/{MM}/{name}` · 公开

- 返回图片流；仅允许白名单文件名；禁止路径穿越。
- 缓存头：`Cache-Control: public, max-age=86400`。

## 10. 点赞 / 收藏（模块 C）

### 10.1 点赞

`PUT /articles/{id}/like` · 登录 · 需 CSRF

- 幂等；重复调用返回成功；计数不重复增加。
- 前端按钮是二态开关：未赞时调 `PUT`，已赞时调 `DELETE`；不要用单个 toggle 接口。
- 自己给自己点赞：允许，但不发通知。
- 响应：

```json
{ "liked": true, "likeCount": 13 }
```

### 10.2 取消点赞

`DELETE /articles/{id}/like` · 登录 · 需 CSRF

```json
{ "liked": false, "likeCount": 12 }
```

- 未点赞时调用也返回成功（幂等）。

### 10.3 收藏

`PUT /articles/{id}/favorite` · 登录 · 需 CSRF

### 15.4 变更规则

- 只改实现不改文档的 PR 不合并。

### 15.5 为什么点赞/收藏用 PUT/DELETE 而不是 toggle

- **UI 仍然是二态开关**：按钮亮/灭，点一下切换。
- **接口拆成“设为开”和“设为关”**：`PUT` / `DELETE` 各自幂等。
- **toggle 的问题**：双击或网络重试会发两次 toggle，第一次赞、第二次取消，最终状态不可预测，计数还可能抖动。
- **PUT/DELETE 的问题**：多一个请求方法，但换来了重试安全；唯一键 + 原子计数保证不会重复加数。

同理，关注用 `PUT/DELETE /users/{id}/follow`，不用 `POST /toggle`。
